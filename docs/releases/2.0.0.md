# pmacs 2.0.0

## Three binaries, and the third is required

An installation is now three binaries: `pmacs`, `pmacs-gpu` and
`pmacs-parse-unit`. Since this release every buffer's syntax parse runs
in `pmacs-parse-unit`, a worker process per buffer, held to a time limit
(`syntax.parse-deadline-ms`) and a memory limit
(`syntax.parse-memory-limit-mb`), so a grammar's crash or runaway parse
costs that buffer's colors and not the session. `pmacs` finds the worker
beside itself, or wherever `syntax.parse-unit-path` names it. **Keep the
three binaries in one directory.** An installation carrying only `pmacs`
and `pmacs-gpu`, as 1.1.0's archive did, highlights nothing, and says so
once.

That change to what an installation must carry is why this is a major
version. The setting that used to parse in the editor instead,
`syntax.isolation = "none"`, is removed: it was the only way to run
without the worker, and it put back exactly the failure the worker
exists to stop. A configuration that still sets it is refused, naming the
setting's one remaining choice, `process`.

A package whose `pmacs_required` excludes 2.0.0, as the common
`">=1.0.0, <2.0.0"` does, is refused at install with both versions
named; widen its range to load it.

Before an archive is published, the release now unpacks it and makes its
worker parse: this repository's own files, every bundled grammar's
upstream sources at pinned commits, and the inputs that took the editor
down before the worker existed. A worker stopped by its own limits
passes; one that crashes, or does not answer, fails the release.

## What changed since 1.1.0

Before the roadmap's phases began, in August: the bottom panel's last
stage, zoom on the GPU, long lines (`ui.line-wrap`, honored by both
frontends) and horizontal scrolling on both, `*git-status*` and
`*git-diff*`, LaTeX served by texlab, fixes to the language servers'
file watching, GPU text input that no longer truncates multi-character
input, and GPU pointer and scroll handling.

Then, in order:

- The required reading was cut down to what a change must not break, and
  `crdt` became a default feature.
- The first ten minutes work: a confirmation before a destructive
  command, the mark and buffer-wide motion, `C-g` dropping the selection,
  word kills on the kill ring, `C-x k`, `C-x C-w`, `revert-buffer`, the
  zoom chords on both frontends, line numbers on by default, and a
  generated keymap reference.
- The GPU window got desktop basics: it remembers its geometry, lays out
  in logical pixels at the display's scale, titles itself, fails with one
  actionable line instead of a panic, blinks and dims its caret, and
  takes the macOS Command chords.
- The GPU document got a scrollbar and a current-line highlight.
- A project finder on `C-x p f`, workspace symbols on `C-x p s`, and a
  project grep on `C-x p g`.
- Errors have one place: `*errors*`, the status line until looked at,
  and a count on the mode line, on both frontends. A language server
  that dies is said to have died; a diagnostics panel follows its
  publishes.
- Each minibuffer prompt says whether `RET` takes the selection or what
  you typed; the grid shows candidates as a band above the prompt; `TAB`
  completes; consecutive typed characters undo as one step.
- Semantic colors shift with an edit instead of flashing off while the
  server answers.
- Undo reaches what you did last on either frontend.
- Typing on a large real file lands like typing: the document reaches the
  language server as ranged changes, not the whole file per keystroke.
- Git and the language server became things to act on: stage, unstage,
  discard and commit from `*git-status*`, a diff mode with hunk motion,
  format on save under a bound, and completions' additional edits.
- The mode line, the prompts and the keys tell the truth: the language
  server's state is not misreported under ordinary work, a prompt takes
  one key where one key is enough, and `TAB` completes when there is
  nothing to indent.
- `cargo check` diagnostics arrive: saving now tells the server, so
  rust-analyzer's check runs on save.
- Wrapping means word wrapping, on both frontends.
- Haskell, with haskell-language-server.
- A bad grammar can no longer take the editor down unnoticed: every
  bundled grammar is fuzzed as it ships, and four whose parses aborted or
  never returned were unbundled.
- The grammar gate became able to fail, and two of those four, Haskell
  and YAML, came back with their defects fixed.
- Every buffer's parse runs in a worker process held to time and memory
  (above).
- Hover and signature help appear in a popup at the caret, on both
  frontends.
- `C-x b` reaches the buffer you named, and says which one it reached.

And in this release: markdown is highlighted (headings, emphasis, strong
text, code, links, list and block-quote markers), where until now it
parsed correctly and painted almost entirely plain. In the terminal
frontend under the default word wrap, the colors below a wrapped line
land on the wrong rows, as the line numbers do (#335, #314); this is
older than the release and holds for every language, but prose wraps
most. `ui.line-wrap = "truncate"` avoids it; the GPU frontend is not
affected.

## Four things to know

**JavaScript, JSX, TypeScript and TSX are not highlighted.** Their
grammars (tree-sitter-javascript 0.25.0, and the TypeScript and TSX
grammars) never return from a 24-byte file of unclosed brackets, and grow
without bound while they try, so they are not bundled. tsserver still
serves all four, uncolored. That premise changed in this release: such a
parse is now stopped in its worker at the deadline instead of hanging the
editor, so bringing them back is a clean 600-second fuzz run and the
maintainer's decision, not an open safety question.

**A project reached through a symbolic link gets no answers from its
language server at all** (#317). pmacs canonicalizes the project's root
but not the document's URI, so the server is told about a file outside
the root it was given. This matters most on the `macos-arm64` archive:
on macOS `/tmp` and `/var` are themselves symbolic links, so a project
under either is reached through one.

**The commit this release is cut from has red CI, on four filed
intermittent rows.** At the time of writing, `main`'s last two
code-bearing CI runs are red: on `a27cdc2`, #282 (its fifth occurrence)
and #316 (its fourth); on `4fade33`, #323 (its third) and #334 (its
first). Each is a test row that loses a wait or a reading on a CI runner,
and none has been diagnosed as a product defect. #323's row measured the
in-editor parse this release removes, and its in-editor half is removed
with it. The release workflow runs no test suite, so these do not stop a
release, and the tagged commit's own run may show some of them again.

**Platforms built.** `linux-x86_64`, built on ubuntu-22.04, and
`macos-arm64` (Apple Silicon), built on macos-15. Nothing else is built:
no Intel macOS, no Windows, no other Linux architecture.
